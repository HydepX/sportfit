# Блок 11. Данные, импорт и резервные копии

Вход: **Профиль → Данные и резервные копии**. В профиле также сохранены экспорт
во «Файлы» и восстановление из внешней копии.

## Локальное хранение

| Файл | Назначение |
| --- | --- |
| `workout_history.sqlite` | SQLite schema/user_version 1, append-only таблица `workouts` и `metadata`, индексы окончания/уровня, JSON-снимок результата и SHA-256 каждой записи |
| `workout_history.v1.json` | Исходная история до миграции; остаётся без изменений, не является обновляемой копией SQLite |
| `active_workout.v1.json` | Черновик, UUID, план/факт, пауза, абсолютный дедлайн отдыха |
| `program_runs.v1.json` | Все прохождения с UUID, снимки назначений, закрытые дни и дополнительный отдых |
| `exercises.v1.json`, `program_12w.v1.json`, `program_archive.v1.json` | Каталог, выбранный план и все импортированные версии |
| `body_measurements.v1.json` | Ручные/явно импортированные JSON-замеры с источниками |
| `profile.v1.json`, `schedule.v1.json`, `completed_sets.json` | Профиль и совместимые прежние данные |
| `journal.v1.json` | `sportfit-journal-v1`: ручная активность, цели, заметки, неизменяемые отчёты, настройки напоминаний |
| `HealthLocal/…` | Отдельный кэш и XML Apple Health; не смешиваются с ручным дневником |
| `Backups/sportfit-*.json` | Локальные автоматические, ручные и предварительные копии |
| `restore-journal.v1.json`, `before-restore.v1.json` | Redo-журнал и исходные файлы перед многокомпонентным восстановлением |

Данные находятся в Documents контейнера. Каталог исключается из автоматического
резервного копирования iOS; ошибка подготовки хранилища блокирует запись. База и
новый дневник используют Data Protection до первой разблокировки; Health-кэш —
полную защиту. Приложение не регистрирует аккаунт и не отправляет записи на сервер.
Экспорт пользователь сохраняет локально вне контейнера; облачный перенос не требуется.

## Миграция и неизменяемая история

Перед первым использованием SQLite читается старая история. Импорт всех результатов
и маркер `legacy_imported` фиксируются одной транзакцией. Сбой не должен выдавать
частично перенесённые записи за полную миграцию. Повторный запуск не импортирует
UUID повторно. Старый JSON сохраняется побайтово, включая активные черновики в
своём отдельном файле. Если старый JSON повреждён, он не перезаписывается.

В SQLite нет методов изменения/удаления завершённой тренировки; триггеры запрещают
UPDATE и DELETE. Добавление того же UUID/содержимого идемпотентно, того же UUID с
другим содержимым — ошибка, без изменения старой записи. Проверяются SHA-256 строк
и соответствие UUID. Повреждённая база не подменяется устаревшим JSON: запись
блокируется до восстановления. Неизвестная будущая версия также отклоняется.
Редактирование подходов работает только в активном черновике. Измерения/активность
можно исправлять; отчёты остаются снимками прежнего состояния.

Импорт замеров атомарный: конфликтующий UUID с другим содержимым отклоняет весь
импорт; повтор того же UUID/содержимого не добавляется. Точное повторение даты,
источника и всех полей замера с новым UUID также не добавляется. Удаление ручных
замеров, активности и отдельных копий требует подтверждения в интерфейсе.

## Копия v4 и совместимость

`sportfit-envelope-v1`: `format`, `sha256`, `payload` (base64 исходных JSON-байтов).
Внутри — `sportfit-backup-v4`, `exportedAt` и полные логические данные:
`workouts`, `activeWorkout`, `manualMeasurements`, `legacySetRecords`, `catalog`,
`program`, `archivedPrograms`, `profile`, `schedule`, `runs`, `journal`.
SQLite восстанавливается из валидированных логических результатов, а не из
непроверенного присланного файла базы. Даты резервной копии — стандартные даты
JSONEncoder (секунды от 2001-01-01 UTC), в отличие от ISO 8601 отчёта.

Читаются v1–v4. V1 допускается без checksum для совместимости; v2–v4 требуют
envelope. V3 требует уровни; v4 — также дневник. У старых копий без дневника
восстанавливается пустой новый дневник. Кэш Health и исходный XML в копию не
включаются; отчёты могут содержать сохранённые сводки их показателей. Это явно
подписано в интерфейсе. SHA-256 обнаруживает случайное повреждение, но не является
паролем, шифрованием или подписью доверенного автора. Максимальный файл — 100 МБ,
размер проверяется перед чтением и разбором.

Автокопия при открытии — не чаще 1 за 24 часа, последние 7 автоматических файлов.
Ручные/предварительные копии автоматически не удаляются. У каждой копии показаны
дата, имя и размер; перед восстановлением — дата, число тренировок/замеров/уровней.
Перед заменой читаемого состояния создаётся отдельная копия `before-restore`, её
можно выбрать в том же списке. Внутренняя копия не переживёт удаление приложения:
нужна внешняя копия через системный экспорт.

## Восстановление и перенос

Сначала checksum/версия/структура, уникальность ID, ссылки на программы/уровни,
статусы закрытых дней, валидность черновика, замеров и дневника. Затем создаётся
новый файл SQLite в отдельном временном каталоге, соединения закрываются. Файлы
и БД заменяются через сохранённый redo-журнал; после прерывания он применяется
при следующем старте. Все хранилища перечитываются. Повторное восстановление —
замена, а не прибавление записей, поэтому UUID не дублируются. Напоминания после
восстановления выключаются, системное разрешение не переносится.

Для другого iPhone: экспортировать JSON вне контейнера, перенести локально,
установить SportFit, восстановить после проверки сводки и сверить число результатов.
Для обновления текущего: **тот же Apple ID и bundle ID, без удаления приложения**.
Установщик должен обновить существующий контейнер. Смена подписи/идентификатора,
удаление и истечение срока бесплатной подписи — отдельные системные условия.

Автотесты: миграция старого JSON, SQLite-перезапуск и триггеры, конфликт UUID,
повреждённые файлы, v3/v4, перенос в другой каталог, повторное восстановление,
сохранение новых сущностей, отсутствие медицинского кэша в копии. После UI-тестов
отдельный симулятор устанавливает .app, мигрирует синтетическую прежнюю JSON-историю,
создаёт автокопию, затем повторно устанавливает .app без удаления и сравнивает байты
Documents, UUID, содержимое результата и контрольную сумму строки SQLite.
Это проверка контейнера симулятора; **обновление через реальную переподпись AltServer
с сохранением данных на физическом iPhone ещё требует подтверждения пользователя**.
