# Блок 08. Статистика и аналитика

Вход: **Прогресс → Статистика и отчёты**. Три раздела используют общие функции
`InsightMath`, `TrainingSummary` и `RunPlanSummary`; эти же функции строят отчёты.
Прямое чтение Apple Health больше не является условием работы приложения.

## Периоды и источники

Неделя/месяц/квартал/год — последние **7/30/90/365 местных календарных дней**, включая
сегодня с 00:00 первого дня до текущего момента. «Всё» — вся записанная история,
без будущих дат. Это скользящие интервалы; календарный квартал выбирается в отчётах.
День тренировки в аналитике — дата сохранённого окончания, а не дата шаблона.

Ручные/JSON-замеры разделены по `BodyMeasurement.source`, XML — по `sourceName`
с явной меткой XML. Выбор источника не смешивает весы, телефон и ручные записи.
Пустой день не означает нулевое значение. Нули учитываются только если записаны
явно и допустимы для показателя (шаги, сон, калории, внешний вес).

## Физическая форма

| Показатель | Единица / формула |
| --- | --- |
| Вес, мышцы | кг, записанное значение |
| Талия, грудь, бёдра | см, записанное значение |
| Жир | %, записанное значение; изменение — **процентные пункты** |
| ИМТ | вес / (рост в метрах)²; только при наличии роста в этом замере |
| Абсолютное изменение | последнее − первое измерение одного источника в периоде |
| Относительное изменение | 100 × (последнее − первое) / первое; недоступно при первом = 0 |
| Среднее | сумма доступных значений / число наблюдений, без заполнения пробелов |

При одном измерении показывается значение, но сравнение недоступно. Для веса:
сначала среднее всех измерений **каждого наблюдавшегося дня** одного источника,
затем среднее этих суточных средних за текущий и предыдущие 6 календарных дней.
Нужно минимум 2 наблюдавшихся дня. Отсутствующие дни не входят в знаменатель.
Так частые взвешивания одного дня не получают больший вес. Тренд рассчитывается
скользящим окном, без квадратичного перебора всей истории.

График: точки исходных измерений и зелёная линия тренда веса. Разрыв более 7 дней
не соединяется линией. На графике максимум последние 5000 точек; сравнение считает
весь выбранный период. Мышечная масса не выводится из безжировой массы. Значения
состава тела не используются для медицинских диагнозов или назначения нагрузки.

## Тренировочный прогресс

- Попытки — уникальные UUID сохранённых результатов, включая частичные.
- Занятие — `runId + runDayIndex`; для прежнего календаря — `programId + date`.
  Несколько попыток одного дня не дают несколько выполненных дней.
- Полное занятие — `WorkoutResult.isComplete`: не досрочное, без пропущенных
  движений, отмечено не меньше назначенного числа подходов. Это **не подтверждение
  выполнения всех назначенных повторов**: план 5 / факт 4 сохраняется как факт.
- Все реальные подходы повторных попыток входят в число подходов и объём работы.
- Повторения не включают длительности и дыхательные циклы; последние считаются
  отдельными показателями. Секунды — сумма фактических длительностей упражнений.
- Время занятия — от создания черновика до зафиксированного окончания минус ручные
  паузы; включает подготовку, отдых и ожидание, а не только активные движения.
- Внешний объём = Σ(фактические повторы × записанный внешний вес). Масса тела не
  подставляется; упражнения на время/дыхание исключаются. Для «на сторону» берётся
  записанное число, без догадки о множителе 2. Это не универсальный показатель силы.
- Регулярность — число разных местных дней с ≥1 подходом и число ISO-недель
  (понедельник–воскресенье) с такими занятиями. Автоматических пропусков нет.
- Прогресс упражнения сравнивает первую и последнюю запись в периоде **одного ID
  и режима**: максимальный вес подхода, сумма повторов/секунд, внешний объём.
  Повторяющиеся движения внутри одной тренировки объединяются. Рост записанного
  объёма не называется ростом силы: он может зависеть от числа подходов.
  Изменение объёма/максимального веса в процентах = `100 × (последнее − первое) / первое`;
  нужны две разные записи занятий и первое значение > 0. При нуле или одной записи
  процент не вычисляется. JSON передаёт исходные первые/последние значения для этого расчёта.

Графики: столбцы подходов по дням; точки рабочего веса и повторов выбранного
упражнения. Фильтр упражнения считает его подходы; длительность относится ко всему
занятию и подписана соответственно. План уровня считает **явно закрытые дни**:
100 × полностью закрытые тренировки / все тренировки снимка программы. Частичные,
явно пропущенные и ещё открытые дни показаны отдельно. Не закрытый сохранённый
результат виден среди фактических тренировок, но не продвигает план.

## Активность и восстановление

Шаги, часы сна и активные ккал вводятся как суточный итог. Для нескольких ручных
записей одного дня берётся последняя по `recordedAt`, а не сумма исправлений.
Пульс — среднее доступных измерений одного источника за день, не live-пульс.
Среднее за период — среднее **наблюдавшихся дней**, с явным числом таких дней.

XML даёт вес/шаги/пульс. Сон и калории вводятся вручную. Для XML-шагов суммируются
только непересекающиеся интервалы одного источника внутри суток. Пересечения или
переход через полночь исключают неопределённый итог из графика. Источники никогда
не складываются. Для шагов/сна/калорий — столбцы; для пульса — точки суточных
средних. Нет данных — нет столбца/точки. Индекс восстановления не выдумывается.
