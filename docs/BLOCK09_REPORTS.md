# Блок 09. Итоги уровня и календарного квартала

Вход: **Прогресс → Статистика и отчёты → Отчёты уровней и кварталов**;
отчёт также доступен в текущем плане и архиве уровня.

## Границы и сохранение

Уровень остаётся последовательностью, без календарного дедлайна. Его отчёт
охватывает местный день начала — фактическое закрытие (или сейчас для предварительного
отчёта). Тренировки выбираются по UUID уровня, поэтому повтор того же шаблона
не смешивается с прежним прохождением. Замеры/активность выбираются по датам.

Календарный квартал выбирается отдельно по году и Q1–Q4: январь–март, апрель–июнь,
июль–сентябрь, октябрь–декабрь. Верхняя граница — момент перед началом следующего
квартала, ограниченная текущим временем. Он включает фактически сохранённые занятия,
но не придумывает плановые календарные занятия или процент соблюдения без знаменателя.

При закрытии уровня приложение автоматически сохраняет полный локальный итоговый
снимок, один на уровень. Предварительные снимки можно сохранять вручную. Снимки
не пересчитываются при последующих замерах, редактировании целей или импорте.
Открытие старого снимка и повторный экспорт не создают новую копию отчёта.

## Содержимое `sportfit-quarter-report-v1`

JSON: UTF-8, даты ISO 8601; это формат отчёта, **не резервная копия для восстановления**.

- `format`, `id`, `createdAt`, `title`, `scope`, `start`, `end`, `isFinal`, `privacy`.
- `training`: уникальные попытки/занятия, подходы, повторы, дыхательные циклы,
  секунды упражнений, длительность, внешний объём, активные дни/ISO-недели,
  сравнение первой/последней записи каждого упражнения и режима.
- `plan`: для уровня — все запланированные, полностью/частично закрытые, явно
  пропущенные, оставшиеся тренировки, дополнительный отдых и серия закрытых занятий.
- `body`: отдельные сравнения веса/жира/мышц/обхватов/ИМТ для каждого источника:
  первое/последнее, даты, число наблюдений, среднее, минимум/максимум. При одном
  наблюдении сравнение недоступно. Жир сравнивается в процентных пунктах.
- `activity`: такие же сравнения суточных показателей шагов/пульса/сна/ккал,
  только при наличии данных и отдельно по источникам.
- `goals`: явная цель, условие, целевое/текущее значение, источник, результат
  `true/false/null`, процент продвижения при доступной исходной точке.
- `profileName`, `notes`: только в полном режиме. Заметки содержат самостоятельно
  выбранную причину/свободный текст, дату, необязательную связь с уровнем и днём.
- `limitations`: правила интерпретации и запрет автоматического назначения нагрузки.

Формулы совпадают с [блоком 08](BLOCK08_ANALYTICS.md).

## Цели и оценка

Числовые цели задаёт пользователь: вес, талия, жир, мышцы, число полностью закрытых
занятий, процент выполнения уровня. Условия «не больше» / «не меньше» задаются явно.
Цели по телу используют выбранный источник ручных/JSON-замеров; XML не подмешивается.
Первое доступное измерение выбранного источника в периоде фиксируется как baseline
при создании цели; для счётчиков исходное значение — 0. Последний доступный замер
в периоде даёт текущее значение. Без него результат `null`, а не «цель провалена».

При выполненном условии продвижение 100%. Иначе, если baseline не выполнял условие
и отличается от target: `clamp(100 × (current − baseline) / (target − baseline), 0, 100)`.
В остальных случаях процент недоступен. Отсутствие целей не превращается в низкую
оценку. Процент соблюдения плана оценивается только у уровня, где есть знаменатель.

## Экспорт и следующий план

Режим по умолчанию — **показатели без имени**: исключены имя, свободные заметки и
пользовательское название отчёта; числовые замеры/активность остаются. **Только
тренировки** дополнительно исключает тело/активность и цели по телу. **Полный**
сохраняет заметки и имя. Ни один режим не обещает полной анонимности.

JSON хранит структурированные показатели. PDF содержит те же выбранные данные
на A4 с переносом русского текста и автоматической пагинацией. В PDF нет скрытого
исходного полного JSON. Файлы создаются локально через системный экспорт; автоматической
отправки нет. Перед передачей проверь состав. Личные файлы не публикуются в GitHub.

Для следующего плана сопоставляются выполненные/частичные/открытые дни, реальные
результаты упражнений, согласованные цели и отмеченные сложности. Новая программа
импортируется отдельным JSON. Приложение не увеличивает нагрузку, не придумывает
медицинские ограничения и не объявляет рост объёма доказательством роста силы.
