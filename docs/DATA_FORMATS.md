# Локальные форматы и обновления

Данные — JSON в Documents приложения (доступны владельцу через «Файлы» / файловый обмен iTunes для аварийного сохранения); существующие имена v1 сохранены. Новые необязательные поля декодируются из старых записей как nil. Повреждённые файлы тренировок/замеров не заменяются пустыми массивами. Восстановление резервной копии v2 использует `restore-journal.v1.json`, повторяемое применение и `before-restore.v1.json` с предыдущими файлами. Журнал не удаляется до окончания всех записей. Не редактируй эти служебные файлы вручную.

## Программы

Импорт через Профиль → program_12w.v1.json. Схема `1.0.0`, непустой `program_id`, строгие локальные даты `yyyy-MM-dd`, целое количество недель, непрерывные непересекающиеся этапы. Все ID упражнений и щадящих замен должны существовать в каталоге. Для нового квартала используй новый program_id. Предыдущий план и все его версии сохраняются в `program_archive.v1.json`. История занятий не переписывается.

Необязательный словарь `prescriptions` в программе:

```json
"prescriptions": {
  "<существующий ID упражнения>": {
    "sets": 2,
    "repetitions": "текст из согласованной программы",
    "restSeconds": 60,
    "progression": "правило из согласованной программы"
  }
}
```

Тот же словарь можно добавить внутрь этапа `phases[]`: назначения этапа имеют приоритет над общими и позволяют задать согласованную прогрессию по неделям. При щадящей замене используется назначение фактически выполняемого ID.

Пример описывает формат, не назначение нагрузки. Исходный план таких правил не содержит. Для упражнений без назначения приложение показывает исходный ориентир каталога и отсутствие количества подходов. Повторы/секунды/вес в результате всегда фактические, отдельно от текстовой цели. При замене упражнения не переносить на него неподходящие назначения без проверки согласованной программы.

## Импорт измерений без HealthKit

Профиль → Импортировать измерения JSON. Это независимый простой формат SportFit, не непосредственный импорт Apple Health export.xml. Даты используют стандартное JSON-кодирование Date Foundation — секунды от 2001-01-01T00:00:00Z. Экспорт SportFit позволяет увидеть тот же формат. Импорт добавляет записи с новыми UUID, повторные UUID не дублируются. Источник указывай явно: `manual`, `Huawei Health (ручной перенос)` и т.п.; приложение не притворяется, что такие записи получены через HealthKit.

```json
[
  {
    "id": "23D39098-6D7D-49C9-B9B1-4136BF10B2D9",
    "measuredAt": 815616000,
    "weightKg": 81.0,
    "waistCm": 80.0,
    "bodyFatPercent": 20.0,
    "heightCm": 180.0,
    "chestCm": 100.0,
    "hipsCm": 95.0,
    "muscleMassKg": 55.0,
    "source": "manual"
  }
]
```

Необязательны все числовые поля, кроме weightKg. Единицы зафиксированы в именах; нельзя подставлять фунты/дюймы. Даты будущего, нечисловые и выходящие за технические диапазоны значения отклоняются. Диапазоны — защита ввода, не медицинские рекомендации.

## Медиа

Собственные проверенные материалы: `SportFit/Resources/media/<id>/loop.mp4` (без звука, зацикленно) и `start.jpg`, `middle.jpg`, `finish.jpg`. Папка media копируется в приложение с сохранением структуры. При отсутствии файлов показывается понятная заглушка и текстовая техника. Не меняй постоянные ID ради медиа. Авторские права и техника проверяются до добавления материалов.

## Резервные копии

Внешний JSON `sportfit-envelope-v1` содержит payload в base64 и его SHA-256. Payload имеет формат `sportfit-backup-v2`. Не редактируй файлы вручную: контрольная сумма перестанет совпадать. SHA-256 выявляет повреждение, но не защищает от намеренной подмены и не шифрует личные данные. Сохраняй копии вне контейнера приложения. Старый прямой экспорт `sportfit-backup-v1` поддерживается; он не содержит программ и профиля, поэтому эти текущие данные при восстановлении v1 сохраняются.


## Программа v2 с отдельными занятиями

`program_12w_with_sets.v2.json` перенесён без изменения из предоставленного архива
BLOCK03_program_with_sets_v2 (1).zip. Каталог архива совпадает с существующими 53 ID.
Схема `2.0.0`: `sessions` содержит 48 уникальных дат; `items` каждого занятия содержат
`sets`, `mode`, `target_reps` / `target_seconds`, `rest_seconds`, этап и дополнительные
ограничения. Режимы: `duration` (секунды), `repetitions`, `repetitions_per_side` (на каждую
сторону), `breath_cycles` (дыхательные циклы). Назначения берутся именно из занятия
выбранной даты, включая облегчённые недели; один общий словарь по ID их не заменяет.

Для v2 условные упражнения с `requires_clearance` требуют явного подтверждения наличия
разрешения врача перед выполнением или пропуска без замены — как указано в новом файле.
Плановые значения не меняются при записи меньшего фактического результата.

Обновление приложения выбирает v2 для новой установки; точная копия исходного v1
обновляется один раз с архивацией старого плана. Собственные изменённые импорты не
заменяются. Записанные результаты и уже начатый черновик сохраняют прежние снимки:
изменение программы не переписывает историю и не подменяет фактические значения.
В копию приложения входят также отдельные занятия, их режимы и назначения.


## Последовательные уровни и копия v3

Актуальные правила и поля: [Блок 05](BLOCK05_PLAN.md). Новые резервные копии имеют
формат `sportfit-backup-v3` и включают массив `runs`. Восстановление старой копии
v1/v2 очищает уровни, которых в такой копии не было, вместе с заменой истории.
Старые результаты и черновики читаются без новых необязательных полей.


## Apple Health XML и приватный кэш

[Блок 07](BLOCK07_HEALTH.md) описывает импорт `export.xml`, нормализацию единиц,
источники и устранение повторов. `HealthLocal/health_cache.v1.json` и
`HealthLocal/health_import.v1.json` не включены в копию тренировок и исключены из
автоматического резервного копирования. Нативные/импортированные показатели не
превращаются автоматически в `BodyMeasurement` и не перезаписывают ручные записи.
