# Локальные форматы и обновления

История — SQLite в workout_history.sqlite; остальные данные — JSON в Documents приложения (доступны владельцу через «Файлы» / файловый обмен iTunes для аварийного сохранения); существующие имена v1 сохранены. Новые необязательные поля декодируются из старых записей как nil. Повреждённые файлы тренировок/замеров не заменяются пустыми массивами. Восстановление резервной копии использует `restore-journal.v1.json`, повторяемое применение и `before-restore.v1.json` с предыдущими файлами. Журнал не удаляется до окончания всех записей. Не редактируй эти служебные файлы вручную.

## Программы

Импорт через Профиль → program_12w.v1.json. Схема `1.0.0`, непустой `program_id`, строгие локальные даты `yyyy-MM-dd`, целое количество недель, непрерывные непересекающиеся этапы. Все ID упражнений и щадящих замен должны существовать в каталоге. Для нового квартала используй новый program_id. Пользовательские версии сохраняются в `program_archive.v1.json`; прежний встроенный план, явно удалённый владельцем, исключён из выбора. История занятий не переписывается.

Необязательный словарь `prescriptions` в программе:

```json
"prescriptions": {
  "<существующий ID упражнения>": {
    "sets": 2,
    "repetitions": "текст из согласованной программы",
    "restSeconds": 60,
    "progression": "правило из согласованной программы"
  }
}
```

Тот же словарь можно добавить внутрь этапа `phases[]`: назначения этапа имеют приоритет над общими и позволяют задать согласованную прогрессию по неделям. При щадящей замене используется назначение фактически выполняемого ID.

Пример описывает формат, не назначение нагрузки. Исходный план таких правил не содержит. Для упражнений без назначения приложение показывает исходный ориентир каталога и отсутствие количества подходов. Повторы/секунды/вес в результате всегда фактические, отдельно от текстовой цели. При замене упражнения не переносить на него неподходящие назначения без проверки согласованной программы.

## Импорт измерений без HealthKit

Профиль → Импортировать измерения JSON. Это независимый простой формат SportFit, не непосредственный импорт Apple Health export.xml. Даты используют стандартное JSON-кодирование Date Foundation — секунды от 2001-01-01T00:00:00Z. Экспорт SportFit позволяет увидеть тот же формат. Импорт добавляет записи с новыми UUID, повторные UUID не дублируются. Источник указывай явно: `manual`, `Huawei Health (ручной перенос)` и т.п.; приложение не притворяется, что такие записи получены через HealthKit.

```json
[
  {
    "id": "23D39098-6D7D-49C9-B9B1-4136BF10B2D9",
    "measuredAt": 815616000,
    "weightKg": 81.0,
    "waistCm": 80.0,
    "bodyFatPercent": 20.0,
    "heightCm": 180.0,
    "chestCm": 100.0,
    "hipsCm": 95.0,
    "muscleMassKg": 55.0,
    "source": "manual"
  }
]
```

Необязательны все числовые поля, кроме weightKg. Единицы зафиксированы в именах; нельзя подставлять фунты/дюймы. Даты будущего, нечисловые и выходящие за технические диапазоны значения отклоняются. Диапазоны — защита ввода, не медицинские рекомендации.

## Медиа

Собственные проверенные материалы: `SportFit/Resources/media/<id>/loop.mp4` (без звука, зацикленно) и `start.jpg`, `middle.jpg`, `finish.jpg`. Папка media копируется в приложение с сохранением структуры. При отсутствии файлов показывается понятная заглушка и текстовая техника. Не меняй постоянные ID ради медиа. Авторские права и техника проверяются до добавления материалов.

## Резервные копии

Внешний JSON `sportfit-envelope-v1` содержит payload в base64 и его SHA-256. Новые payload имеют формат `sportfit-backup-v4`. Не редактируй файлы вручную: контрольная сумма перестанет совпадать. SHA-256 выявляет повреждение, но не защищает от намеренной подмены и не шифрует личные данные. Сохраняй копии вне контейнера приложения. Старый прямой экспорт `sportfit-backup-v1` поддерживается; он не содержит программ и профиля, поэтому эти текущие данные при восстановлении v1 сохраняются.


## Программа v2 с отдельными занятиями

Текущая программа — `sportfit_12w_2026q4`, перенесённая из
`SportFit_12_weeks_Codex.xlsx`: 36 упражнений, 48 тренировок, 624 назначения.
Оба совместимых имени `program_12w*.json` содержат одинаковую схему `2.0.0`.
`sessions` хранит исходный шаблон, даты не являются сроками выполнения.
Уровень использует порядковый индекс дня; результат датируется фактическим выполнением.

`items` сохраняют `source_item_id`, `sets`, `mode`, `target_reps` / `target_seconds`,
`rest_seconds`, `unit`, `load`, `optional` и примечания источника. Одно упражнение
может появиться дважды в занятии: данные связываются с позицией/item_id, не только
с exercise_id. Поддержаны `duration`, `duration_per_side`, `repetitions`,
`repetitions_per_side`, `repetitions_total`; прежний `breath_cycles` читается из истории.
`load` — текстовая рекомендация, а не автоматически записанный рабочий вес.

Для `duration_per_side` план задаёт секунды каждой стороны. Факт хранит `seconds`
и необязательный `otherSideSeconds`. Отсутствующая вторая сторона не считается
выполненной; суммарное время учитывает только записанные значения. Черновик хранит
`currentSide` (1/2) и `firstSideSeconds`, которые переживают паузу и перезапуск.
Результаты и активные снимки назначений не пересчитываются по новой версии плана.

Прежний встроенный ID удаляется из выбора программ. Его уровни имеют `retiredAt`
(не эквивалент `closedAt`); черновики сохраняются в `journal.retiredDrafts` для чтения
и входят в копию v4. Старые 53 ID имеют `retired=true` и доступны истории,
новая библиотека показывает только 36 текущих записей. Маркер `plan_release.v1.json`
защищает последующие импорты от повторной замены. Полные правила и происхождение
фото: [обновление плана](WORKBOOK_PLAN.md).

Фото описывается `media.photo`: `asset` — безопасное имя исходного коллажа в папке
media, `columns`, `rows` — сетка, `index` — ячейка с нуля построчно. Приложение
вырезает нужную ячейку при отображении; исходное изображение не перерисовывается.
Для остальных упражнений остаётся исходная текстовая техника.


## Последовательные уровни и совместимость копий

Актуальные правила и поля: [Блок 05](BLOCK05_PLAN.md). Копии v3 добавили массив `runs`; новые копии v4 добавляют также `journal` с ручной активностью, целями, заметками, отчётами и настройками напоминаний. Восстановление старой копии
v1/v2 очищает уровни, которых в такой копии не было, вместе с заменой истории.
Старые результаты и черновики читаются без новых необязательных полей.


## Apple Health XML и приватный кэш

[Блок 07](BLOCK07_HEALTH.md) описывает импорт `export.xml`, нормализацию единиц,
источники и устранение повторов. `HealthLocal/health_cache.v1.json` и
